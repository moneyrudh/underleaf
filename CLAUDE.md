# underleaf

Local, Overleaf-style LaTeX workspace in the browser: file tree | embedded Claude Code terminal | live PDF preview. A bun server watches `latex/`, recompiles on save, and pushes results over WebSockets. The repo is about the **tool**; direction is toward an AI resume-tailoring agent built on it.

## Commands

- `bun dev [folder] [--port N] [--no-open]` — the app (default folder: the last one opened, else the checkout's `latex/`; port 4747)
- `bun run dev:ui` — same, with Bun dev mode (HMR, browser errors echoed to terminal) for working on `public/`. The UI is bundled at server start otherwise, so restart after frontend edits.
- `bun run pdf <file.tex> [out.pdf]` — one-shot export
- `bun run doctor` — check bun / TeX engines / latexmk, print install hints
- `bun run typecheck` — must pass before committing (`bunx --bun tsc`; TS 7 doesn't run on the system Node)
- `bun run smoke` — end-to-end check in headless Chrome (`--keep` leaves the scratch folder). Scratch workspace + seeded history in a temp dir, its own `UNDERLEAF_HOME`, and a stand-in `claude` via `UNDERLEAF_CLAUDE_BIN`, so it never touches your files, history or Claude account. Run it before and after anything structural; add a check when you add a feature.

## Layout

- `src/build/compile.ts` — engine detection (`% !TEX program`, fontspec → xelatex, else pdflatex), latexmk if installed else engine ×≤4 passes with BibTeX after the first when the `.aux` has `\bibdata` (`BIBINPUTS` points back at the sources; `.blg` problems become diagnostics), log → diagnostics (unwrapped via `max_print_line` env). `\include{dir/x}` needs `dir/` in the output folder, so it's created first.
- `src/workspace/files.ts` — tree scan (skips dotfiles/symlinks; `doc` = .tex with `\documentclass`), `resolveTreePath` (realpath containment check), `keepWatching` (recursive fs.watch + 1s inode health check that recreates deleted/replaced roots).
- `public/claude/terminal.ts` maps keys xterm.js doesn't translate (Shift+Enter → `\n`, ⌘⌫ → Ctrl+U, ⌥⌫ → ESC DEL, ⌘/⌥ arrows → readline moves) via `attachCustomKeyEventHandler`.
- `src/claude/session.ts` — starts with `--continue` (falls back to a fresh session if that exits non-zero within 5s), waits for the pane's first resize before spawning, and warns in the pane when `~/.claude.json` isn't readable (root-owned from `sudo claude` → onboarding every launch). One shared `claude` PTY via `Bun.spawn({ terminal })`, 512KB scrollback replayed on reconnect, Enter restarts after exit. Runs the user's **unmodified** `claude` with their own login (per Anthropic's terms; the Agent SDK would require API keys for a distributed app).
- **Layout.** `shared/` holds what both sides use: `types.ts` (FileNode, Snapshot, Diagnostic, ClaudeStart…) and `protocol.ts` (the `API` and `SOCKETS` paths, the `url()` builder, every websocket message, every request/response body). Never hard-code an `/api/…` path or redefine a message shape on one side; change `protocol.ts` and let the typecheck find both ends. Server responses use `satisfies <Type>` so they're checked against it.
- `src/server.ts` and `src/cli.ts` are entry points; `src/repo.ts` is `REPO` (keep it at `src/` top level, it's computed from its own location). Folders: `server/` (`config` args/folders, `routes` HTTP + WS, `clients` tabs + the shared `ClaudeSession` + hook token, `watch` fs changes → rescan/rebuild/edit snapshot, `trees` scanned trees, doc list, workspace brief), `build/` (`compile`, `builds` per-doc queue, last good PDF, `isStale`, export), `history/` (`store` = HistoryStore, `snapshots` triggers, Claude turn state, old-version builds), `workspace/` (`files` scan/kinds/watch, `templates` list/apply/instructions, `claude-settings` hooks + guardrails merge, `guardrails` permission rules), `claude/` (`session`, `brief`).
- `src/server/routes.ts` — binds 127.0.0.1; `trusted()` checks Host + Origin on all APIs and WS upgrades. Tree paths are `latex/…` whatever the folder is called (the root key; the folder's name is only displayed). Routes are listed in `shared/protocol.ts`. WS `/ws` (workspace, tree, compile and history events) and `/claude` (PTY).
- **Workspaces** (`src/server/workspace.ts`): one open folder at a time (`active`, `current()`); `openWorkspace(dir)` is serialized and swaps everything tied to a folder: flushes the old edit snapshot, stops the watcher, closes history and old-version builds, clears build state, then writes Claude settings and instructions, opens history, watches, rescans, remembers it in `~/.underleaf/workspaces.json` (`workspace/registry.ts`), moves the Claude session there (`--continue`), and broadcasts a `workspace` message then the tree. `generation` bumps on every switch so a build still running for the old folder is discarded. Every folder gets `.underleaf/` (id, instructions, status) and the Claude settings (hooks + guardrails); nothing else is added unless the user picks a template. `startFromTemplate(name)` (same queue) fills an empty workspace, then renews the Claude session so it gets the template's instructions. `unusable(dir)` refuses `/`, home, Desktop/Documents/Downloads, underleaf's own folders and their parents. **Open folder…** runs the system folder dialog on the server (`workspace/pick.ts`: osascript / PowerShell / zenity / kdialog), since a page can't learn a real path. The page reloads when the workspace id changes; per-workspace localStorage keys (selected, recent, expanded) are scoped by workspace id (`setStorageScope`).
- **Saving** (`public/files/save.ts`): there's no exports folder. ⌘S writes to the file this document was last saved to (a `FileSystemFileHandle` kept in IndexedDB per workspace + document), the first time it's Save As; Save As uses `showSaveFilePicker` (Chromium); Save to Downloads is a plain download; without the picker, both fall back to downloading. Each save POSTs `/api/saved`, an empty "export" commit labelled "Saved as x.pdf" / "Downloaded x.pdf".
- `public/core/keys.ts` — keymap: capture-phase window listener so app chords beat xterm. Layers: `global` (mod+p, mod+shift+p, mod+s — fire even in Claude), `leader` (Ctrl+Space then a key), `pane` (vim keys, only when tree/preview focused and not typing; supports sequences like "g g"). Never bind plain Esc or ctrl-letter chords globally — Claude Code needs them.
- `public/ui/hints.ts` — every control with a shortcut shows it: `data-key` on a text button adds a `kbd.k` chip; `data-tip` gives a styled tooltip (with the key) instead, used for icon buttons. Don't use `title` for these. `LEADER` in `data-key` resolves to the platform leader.
- `public/ui/menu.ts` — anchored dropdown with filter + keyboard (used by the compare pickers); never use native `<select>`.
- `public/ui/popover.ts` — toolbar menus (Fit ▾, ⋯): a button with `aria-controls` opens the `.popover` with that id; `[role=menuitem][data-command="<id>"]` runs that registry command (`Command.id`) and is hidden while the command's `when()` is false. Prefer adding an item that points at a command over a one-off handler.
- **Styles** live in `public/styles/` (`style.css` only imports them): `tokens.css` is the only place colors, fonts and shadows are defined (light by default, dark via `prefers-color-scheme`); every other file uses the tokens, never raw colors. One file per area: `base` (buttons `.ibtn` / `.primary` / `.ghost` / `.select`, `kbd`, `.badge`), `shell`, `tree`, `claude`, `preview` (incl. editing on the page), `editor` (Source and the text editor), `history`, `compare`, `overlays`. Fonts are bundled (`@fontsource`, Latin subsets) so the app works offline: Instrument Sans (UI), JetBrains Mono (code, keys, the terminal), STIX Two Text (italic: the wordmark; regular: the text box for editing on the page). Claude's terminal stays dark in both themes (its xterm theme in `claude/terminal.ts` mirrors `--term`).
- `public/ui/palette.ts` — fuzzy picker shared by quick-open and the command palette (best-alignment subsequence scoring).
- **Source editor** (`public/editor/editor.ts`, CodeMirror 6 + the `stex` legacy mode; colors are `--syn-*` tokens): a document's LaTeX opens in the middle column's Source tab (`#claude-pane[data-mid="claude|source"]`, `e`, `STORED.middle`); other text files fill the preview (`#preview-body[data-editor="full"]`), which `editor.css` hides with `:has()` while an earlier version or a comparison is on screen. Saves are automatic after `SAVE_IDLE_MS` (⌘S routes to `editor.flush()` when an on-screen editor has focus, else Save PDF) through `saveFile` → `POST /api/file/save` with `base` = SHA-256 of the version it started from: 409 + the disk text if the file moved on; otherwise a hidden temp file + rename. `editor.changedOnDisk` ignores its own saves (same hash), takes the new text if clean, shows the `.editor-conflict` bars if dirty. `applyEdits(path, base, changes)` takes edits made on the page when that file is open and still `base`.
- **Editing on the page** (`public/preview/pageedit.ts` + `sourcemap.ts`): only `showPdf(url, { editable: true })` (the live document's good build, from `connection.ts`) collects pdf.js text per page and lays an `.edit-layer` over each `.page-wrap`. `sourcemap.ts` reads the LaTeX as a reader sees it (commands/braces/comments/preamble print nothing except `\title`/`\author`/`\date`; `HIDDEN_ARG` commands like `\label`, `\href`'s URL, `\cite` are skipped; escapes, `~`, `--`, quotes become what TeX prints; math is a gap; `\input`/`\include` are read in place), keeping each visible word's source range, then aligns those words with the page's (`wordsFrom`) by a word diff, so repeated phrases map by order. Each source word also has a **component**: the brace group of a command's argument (`owners`; an argument may follow after spaces and one line break, as TeX allows), unless the command is `INLINE` formatting (`\textbf`, `\href`, sizes…), else the stretch since the last blank line / `\item` / `\\` / environment boundary (`BREAKS`). The page's mapped words are grouped by component into an `.edit-target` with one `.edit-rect` per printed line; clicking opens an `.edit-input` textarea with those words; on Enter/blur a word diff becomes source changes (same word count → each word in place; otherwise one stretch, refused if the gap between words isn't plain text), and `breaksStructure` refuses anything whose removed text has unbalanced braces or `\begin`/`\end`/`\item`. Writes go through `editor.applyEdits` or `saveFile`; the pending box stays until the rebuilt page replaces it.
- `public/app.ts` is startup only; one folder per feature. `core/`: `state` (open file, last PDF, roots, recent; toolbar refs), `connection` (WS + message handling), `commands` (**the one registry**: every command with title, keys, scope; keymaps, palette and cheat sheet are generated from it, so add shortcuts there and nowhere else), `keys`, `layout` (panes, focus/`data-focused`, zoom, splitters, the terminal), `util` (`$`, `storage` + **`STORED`, the list of every localStorage key**, toast). `files/`: `tree` (cursor ≠ opened file; changed-file flash), `open` (open/reopen, tree sync, export, mention, quick-open). `preview/preview` (pdf.js v6: `getDocument({url})`, `render({canvas, viewport})`, destroy via loading task; off-screen render then swap). `history/`: `panel` (version bar + History panel), `versions` (view/restore). `compare/`: `compare` (flows), `view` (DiffView), `diffcore`, `ink`. `claude/terminal` (xterm.js + fit addon). `ui/`: `palette`, `menu`, `hints`, `cheatsheet`. Modules import each other in cycles; only touch other modules' exports inside functions, never at module top level. Element ids looked up with `$("…")` must exist in `index.html` (`bun run smoke` checks).
- `build/`, `latex/`, `resumes/` are git-ignored (`resumes/` is from before workspaces: no longer used, left on disk). `examples/` holds committed demo docs. `templates/` is committed: see "The in-app agent". Anything the in-app agent may personalize (its CLAUDE.md, memory, skills) must ship from `templates/`, never be tracked inside `latex/`.

## Version history

- Compare: `public/compare/diffcore.ts` is DOM-free (pdf.js text runs → words with PDF-unit boxes, joining runs split at kerns and dehyphenating line ends; `diffWords` via jsdiff `diffArrays`; `diffSource` = line diff + word marks + folding). `public/compare/view.ts` (`DiffView`) renders both PDFs in one scroller (two grid columns, so they scroll together), plus the source view. Highlight positions come from the rendered pixels (`PageInk`, `public/compare/ink.ts`): pdf.js only gives a run's total width and justified text stretches spaces, so the k widest blank columns in a run are its k spaces and each word is trimmed to its ink; pages with changes are re-rendered off-screen at ≥3 px/pt when the display is 1x. No server changes: sides load from `/api/pdf`, `/api/file`, `/api/history/pdf`, `/api/history/file`. While comparing, `versions.viewing` = the "before" side (so the strip and `,`/`.` move it) and the banner is hidden by `.viewer-col.comparing`.
- `src/history/store.ts`: `HistoryStore` = plain git with `--git-dir=~/.underleaf/history/<id>.git --work-tree=latex/` (`UNDERLEAF_HOME` overrides the root). Workspace id lives in `latex/.underleaf/id` so history survives moving the folder. Snapshot kind/author live in commit trailers (`Underleaf-Kind`, `Underleaf-Path`); authors are `You`/`Claude`/`underleaf`. All git ops are serialized (index.lock). `log()` = `--follow -M` for the file plus exports grepped by exact `Underleaf-Path`, ordered by `rev-list` rank (git times are 1s resolution).
- Triggers (`src/history/snapshots.ts`): edit debounce `EDIT_IDLE_MS` (skipped while a Claude turn is active), Claude `Stop` hook, export (empty commit). Restore snapshots the current state first.
- Claude settings: `ensureClaudeSettings` (`workspace/claude-settings.ts`) merges underleaf's part into `<workspace>/.claude/settings.json` on every start. **Guardrails** (`workspace/guardrails.ts`): deny/ask permission rules plus `blockWritesOutsideWorkingDirectories`; the rules it wrote last time are recorded in `.underleaf/managed-settings.json`, so dropped rules are removed and the user's own rules are never touched. Change the rules there, nowhere else; the instructions (`templates/instructions.md`) describe them to Claude, so keep both in step. **Hooks** (only with git): two `http` hooks (UserPromptSubmit → `?event=prompt`, Stop → `?event=stop`) into `latex/.claude/settings.json` on every start (URL can't interpolate env, so the port is written in). Auth = per-run `UNDERLEAF_HOOK_TOKEN` header passed via `allowedEnvVars`; respond 204 with an empty body (UserPromptSubmit output would be added to Claude's context).
- Past versions compile into `build/<ws>/.history/<commit>/` from `git archive | tar`; `/api/history/pdf` caches per (commit, doc).

## Rules

- **Never commit anything from `latex/` or `resumes/`.** The remote (`github.com/moneyrudh/underleaf`) is public and the author's resumes live there locally.
- File names are untrusted in the UI: `textContent`, never `innerHTML`.
- No Overleaf or Claude Code branding in the product name/logo; plain-text "runs Claude Code" is fine.

## The in-app agent (`templates/` → the workspace)

- `templates/instructions.md` is what every workspace's Claude gets; `templates/<name>/` (`resume`, `thesis`, `article`, `blank`) has `template.json` (title, description, file to open, shared `skills` from `templates/_skills/`), `files/` (copied once, never over an existing file; `.claude/settings.json` is filled in key by key since underleaf's part is already there) and optional `instructions.md` (notes for that kind of document). `src/workspace/templates.ts` does the listing and applying; the page shows the picker when the tree has no `.tex` (`public/files/templates.ts`), and `bun run new <folder> --template <name>` does it from the CLI. Templates are public: never put real personal data in them.
- The workspace's template is recorded in `.underleaf/template` (resume workspaces from before templates are recognized by `.claude/skills/tailor-resume`). `writeInstructions` composes `.underleaf/instructions.md` = shared part + template notes on every start. Claude gets it via `--append-system-prompt-file`, except when the workspace's `CLAUDE.md` already imports `@.underleaf/instructions.md` (pre-template resume workspaces), so it never gets two copies. A `--continue`d conversation keeps the instructions it started with until it's compacted.
- `src/claude/brief.ts` writes `latex/.underleaf/workspace.md` (docs, compile status, pages, errors, overfull lines, open file, exports), debounced after rescans and builds. Template CLAUDE.md files import it; instructions tell Claude to read it before its first change and after saving.
- Server builds every document once at startup, then on change rebuilds open docs + any document that itself changed, so the snapshot covers files nobody has open. Hidden paths (`.underleaf/`, `.claude/`) are ignored by the watcher.
- The checkout's own `latex/` gets `autoMemoryEnabled: false` (`ensureClaudeSettings(…, { insideCheckout })`): it's inside this repo, and auto memory is keyed per git repo, so it would otherwise be shared with dev sessions here. The resume template turns it off everywhere, since `memory/` is its memory.
- The agent also reads this file (parent directory). Its instructions treat it as background only; keep anything the agent needs in `templates/`, since binary users won't have this repo.
